# Распознавание речи (ASR) в конвертере — проект

**Дата постановки:** 2026-10-02.
**Заказчик:** владелец репозитория.
**Смежная система:** собственный сервер распознавания речи — WhisperX (модель
`large-v3-turbo`, выравнивание слов, разметка говорящих pyannote) за HTTP-шлюзом.
Здесь он называется просто «сервер». Адрес, ключ и пин сертификата сервера в
репозиторий не попадают: они живут только в некоммитимом `ffmpeg/config.ini`.

Скрипты `ffmpeg/` получают отдельный режим: файлы из `[folders] source` не
перекодируются, а расшифровываются на сервере; результат — текст с говорящими и
сырой ответ сервера в `[folders] destination`.

## 1. Зачем

Расшифровка записей встреч и видео сейчас делается вручную: извлечь звук, проверить
длительность, при необходимости нарезать, отправить curl'ом, собрать текст из JSON.
Конвертер уже умеет главное из этого — обходить папки, зеркалить подпапки, звать
ffmpeg/ffprobe, пропускать готовое, печатать сводку, — не хватает клиента сервера и
сборки текста.

## 2. Утверждённые решения

| Вопрос | Решение |
|---|---|
| Сочетание с конвертацией | Отдельный режим `[asr] enabled = yes`: только расшифровка, без перекодирования |
| Файлы результата | `<имя>.txt` (реплики с говорящими) и `<имя>.asr.json` (сырой ответ) |
| Разметка говорящих | По умолчанию включена (`diarize = yes`) |
| Платформы | `.sh`, `.ps1`, GUI. `.cmd` — предупреждение и выход с ненулевым кодом |
| HTTP-клиент | curl на обеих платформах (в Windows — системный `curl.exe`) |
| Разбор JSON | `.sh` — один вызов `awk` (без jq/python), `.ps1` — `ConvertFrom-Json`; вывод байт в байт одинаков |
| Звук на сервер | Извлекается локально: первая звуковая дорожка → FLAC, моно, 16 кГц |
| Адрес | Список адресов через пробел; берётся первый, ответивший 200 на `GET /speech/limits` |

Почему curl и в `.ps1`: у сервера самоподписанный сертификат, выписанный на другое
имя, поэтому проверка TLS заменена закреплением открытого ключа. curl делает это
флагом `--pinnedpubkey` (проверено 2026-10-02: системный `curl.exe` 8.x на Schannel
и curl из Git Bash оба обрывают соединение с кодом 90 при чужом пине и открывают
файлы с кириллицей в пути). В .NET Framework то же требует callback'а проверки
сертификата с ручным разбором DER до `subjectPublicKeyInfo` — больше кода и
риск выполнения scriptblock'а вне runspace. Существующий `remote_client.ps1`
остаётся на `HttpWebRequest`: ему пин не нужен.

Почему FLAC: кодер встроен в любую сборку ffmpeg (в отличие от libmp3lame/libopus),
сжатие без потерь не ставит вопроса о качестве, час моно 16 кГц — около 65 МБ при
пределе сервера 500 МБ. Видео целиком на сервер не уходит.

## 3. Контракт сервера (как его видит клиент)

Все запросы — с заголовком `Authorization: Bearer <ключ>` (`x-api-key` не работает).

**`GET <endpoint>/speech/limits`** → `200` и JSON; клиент читает поля:

| Поле | Пример | Использование |
|---|---|---|
| `max_seconds` | `3600.0` | потолок длительности одного запроса |
| `max_bytes` | `524288000` | потолок размера файла |
| `languages` | `["en","ru"]` | проверка `[asr] language` |
| `device` | `"cpu"` / `"cuda"` | коэффициент скорости в плане нарезки |
| `job_timeout_sec` | `1800.0` | серверный предел задачи; клиентский таймаут = он + 300 |
| `diarization` | `true` | при `false` и `diarize = yes` — предупреждение, запрос всё равно уходит |

**`POST <endpoint>/speech/transcriptions`**, `multipart/form-data`: `file`,
`model=whisperx`, `language`, `diarize=true|false`, `num_speakers` (только если
задан; вместе с `min_speakers`/`max_speakers` сервер отвечает `400`, клиент их не
шлёт). Запрос синхронный: ответ приходит после окончания распознавания, соединение
всё это время молчит. У сервера один рабочий поток — запросы шлются строго по одному.

**Ответ `200`:** `text`, `language`, `asr_ver`, `segments[]` (`start`, `end`,
`text`, `speaker` — может отсутствовать, `confidence` — может отсутствовать,
`words[]` — клиентом не читается), `stages` (`transcribe`/`align`/`diarize` →
`status`), `warnings[]`, `audio_seconds`, `processing_seconds`. `200` не означает,
что разметка сделана: статус этапов проверяется.

**Ошибки** — JSON `{"detail": "..."}` по-русски, выводится дословно.

**Ловушки шлюза:** `/v1/audio/transcriptions` отвечает `400 «Invalid model name»`
(встроенный обработчик шлюза, не наш маршрут); модели `whisperx` нет в `/v1/models` —
так и должно быть.

## 4. Конфиг: секция `[asr]`

```ini
[asr]
# Расшифровать файлы на сервере распознавания вместо конвертации (yes/no)
enabled = no
# Базовый адрес шлюза без пути: https://<хост>:<порт>. Несколько адресов — через
# пробел, берётся первый ответивший. Подстановка: endpoint = ${ASR_URL}
endpoint =
# Bearer-ключ или ${ASR_API_KEY}
api_key =
# Ключ со stdout команды; приоритет выше api_key
api_key_command =
# Закреплённый открытый ключ сервера: sha256//<base64>. Для https с
# самоподписанным сертификатом обязателен
pinned_pubkey =
# Язык записи: из languages сервера (сейчас ru, en). Автоопределения нет
language = ru
# Разметка говорящих (yes/no)
diarize = yes
# Число говорящих, если точно известно (1–50); пусто — сервер определит сам
num_speakers =
```

- `${VAR}` в `[asr]` не печатает WARN о незаданной переменной (как `[remote]`):
  о пустом адресе или ключе говорит проверка перед прогоном.
- Ключи `[asr]` по именам пересекаются с `[remote]` (`enabled`, `endpoint`,
  `api_key`, `api_key_command`). Поэтому `tests/common/test_config_keys.sh`
  становится зависимым от секции: сейчас он сверяет имена без секций и пропустил бы
  отсутствующее чтение `[asr] enabled` за счёт `[remote] enabled`.
- TLS: `https` + `pinned_pubkey` → `-k --pinnedpubkey …`; `https` без пина →
  обычная проверка curl (на самоподписанном сертификате — понятная ошибка с
  подсказкой про `pinned_pubkey`); `-k` без пина не ставится никогда. `http` —
  разрешён, один раз печатается `[ПРЕДУПРЕЖДЕНИЕ]`: ключ и звук идут открытыми.
- GUI и `--print-config` ключ не показывают целиком (маска, как у `[remote]`).

## 5. Прогон

### 5.1. Перед первым файлом

1. Проверка конфига: `endpoint` не пуст и каждый адрес начинается с `http://` или
   `https://`; ключ получен (`api_key_command` → `api_key`); `num_speakers` пуст или
   целое 1–50; `language` не пуст; `diarize` — `yes` или `no`; найдены curl и
   локальный ffmpeg.
2. Выбор адреса: адреса из `endpoint` по порядку, `GET /speech/limits` с
   `--connect-timeout 5 --max-time 15`. Первый `200` с разбираемым JSON — рабочий.
   `401`/`403` и curl с кодом `90` — остановка сразу (ключ общий для всех адресов,
   чужой сертификат — повод остановиться, а не искать дальше). Остальное —
   следующий адрес. Никто не ответил — остановка со списком «адрес → результат».
3. `language` ∉ `languages` — остановка (если сервер список объявил: молчание
   сервера не повод отказывать).
4. `parallel_files` в этом режиме не действует: файлы идут строго по одному
   (при значении > 1 — одна строка `[ПРЕДУПРЕЖДЕНИЕ]`).

Остановка до первого файла — код возврата 1, ни один файл не тронут.

### 5.2. Файл

Набор входов, зеркало подпапок и имена — те же, что у конвертера
(`format_files_in`, `file_path`, `save_old_extension`). Выходы:
`<destination>/<file_path>/<file_name>.txt` и `….asr.json`.

1. **Пропуск.** `overwrite_existing = no` и `.txt` существует → `skip`. `.txt`
   публикуется последним, поэтому служит маркером готовности.
2. **Длительность и звук.** Разбор вывода `ffmpeg -i` — тот же, что у конвертера
   (`parse_media_info` в `.sh`, `Duration:`/`Stream … Audio:` в `.ps1`; ffprobe
   конвертер не использует): длительность в целых секундах плюс 1 с вместо дробной
   части и наличие звуковой дорожки. Нет звука или длительность не читается →
   `fail` с причиной.
3. **План частей** (§6).
4. **Извлечение** каждой части во временный каталог (§7).
5. **Распознавание** частей по одной (§8).
6. **Публикация** (§9): во временные имена в каталоге назначения, затем
   переименование — `.asr.json`, последним `.txt`.
7. Временный каталог удаляется в любом исходе (trap / `finally`).

### 5.3. Исходы

- **Файл провален** (`fail`, прогон продолжается) — причины, привязанные к файлу:
  ошибка извлечения, нет звука, `400`, `413`, `422`, `200` с неразбираемым JSON.
- **Прогон остановлен** — причины, общие для всех файлов: `401`, `403`, `500`, `502`,
  `504`, `503` после повторов, curl `90` (чужой сертификат), curl `6`/`7`/`28` и
  прочие сетевые сбои. Текущий файл — `fail`, оставшиеся — «не обработано» в сводке.
  `504` не повторяется: задача на сервере продолжает выполняться и занимает очередь.
- `503` (очередь заполнена) — пауза 60 с и повтор, не больше 5 раз.

## 6. План частей

Исходные данные: `D` — длительность в секундах, округлённая вверх; из
`/speech/limits`: `max_seconds`, `job_timeout_sec`, `device`.

```
k = 0.6, если device = "cpu", иначе 0.1      # секунд обработки на секунду записи, с запасом
W = floor(min(max_seconds, job_timeout_sec / k))   # предел «целиком»
если D ≤ W:  одна часть [0, D)
иначе:
  P = floor(W / 2)          # потолок части
  n = ceil(D / P)
  L = ceil(D / n)           # равные части, без крошечного хвоста
  часть i (0..n-1): смещение i·L, длина min(L, D − i·L)
```

Сейчас (`cpu`, 3600, 1800): `W = 3000`, `P = 1500`. Примеры: 2999 с → целиком;
3001 с → 3 части по 1001 с; 5400 с → 4 части по 1350 с. На `cuda` (7200): `W = 7200`.
План считается одинаково в `.sh` (целочисленная арифметика, коэффициент как 6/10 и
1/10) и `.ps1`; паритет плана закреплён тестом.

Слово на стыке частей может разрезаться — принятая цена. Метки говорящих в разных
частях независимы: `SPEAKER_00` первой части не обязательно тот же человек во второй.

## 7. Извлечение звука

```
ffmpeg -nostdin -v error -y [-ss <смещение> -t <длина>] -i <вход>
       -map 0:a:0 -vn -ac 1 -ar 16000 -c:a flac <tmp>/part_<NNN>.flac
```

`-ss`/`-t` — только при нескольких частях, на входной стороне: кодирование заново,
смещение точное. Имя временного файла — латиница без пробелов. Размер части больше
`max_bytes` → `fail` (при текущих пределах недостижимо: час ≈ 65 МБ).

## 8. Запрос

```
curl -sS --config -                       # stdin: header = "Authorization: Bearer …"
     [-k --pinnedpubkey <pin>]            # только https с пином
     --connect-timeout 10 --max-time <job_timeout_sec + 300>
     -F "file=@part_NNN.flac;type=audio/flac"
     -F model=whisperx -F language=<lang> -F diarize=<true|false>
     [-F num_speakers=<N>]
     -o resp_NNN.json -w "%{http_code}"
     <endpoint>/speech/transcriptions
```

- curl запускается из временного каталога прогона, часть и ответ — относительными
  именами. curl из Git Bash — нативная программа: путь `file=@/tmp/…` MSYS в
  Windows-путь не переводит, и curl отвечает кодом 26 (проверено 2026-10-02).
- Ключ — только через stdin (`--config -`), не в argv, не в логах, не в выводе
  dry_run.
- Перед запросом печатается строка «распознавание <файл> (часть i/n, <длительность>)…»,
  после ответа — время ожидания: молчащее соединение — норма, а не зависание.
- Отмена: Ctrl+C в `.sh`; в GUI — кнопка «Стоп» убивает процесс curl тем же
  механизмом, каким воркер GUI останавливает ffmpeg; временный каталог удаляется.

## 9. Результаты

### 9.1. `<имя>.asr.json`

- Одна часть — тело ответа без изменений.
- Несколько частей — обёртка без пересборки ответов:
  `{"chunks":[{"offset_seconds":0,"response":{…}},{"offset_seconds":1001,"response":{…}}]}`.
  Время внутри `response` — от начала своей части; смещение указано явно.

### 9.2. `<имя>.txt`

UTF-8 без BOM, переводы строк LF. Шапка, пустая строка, реплики:

```
# Расшифровка: <имя исходного файла с расширением>
# Дата: YYYY-MM-DD HH:MM
# Модель: <asr_ver>
# Длительность записи: HH:MM:SS, обработка: HH:MM:SS
# Говорящих: <N>
# Частей: <n> по ≈HH:MM:SS — метки говорящих в разных частях независимы
# Сомнительных сегментов (confidence < 0.6): <K>; первые: HH:MM:SS, HH:MM:SS, HH:MM:SS
# Этапы с ошибкой: diarize=failed, align=unavailable
# Предупреждение: <текст>

[00:00:03] SPEAKER_00: Добрый день, начинаем...
[00:00:41] SPEAKER_01: ...
```

Правила (одинаковые на обеих платформах — по ним сверяется паритет):

- Строка «Частей» — только при n > 1; «Говорящих» тогда пишется по частям:
  `# Говорящих по частям: 2, 3`.
- «Этапы с ошибкой» — только если есть этап со статусом не `ok` (статус не указан —
  `?`); «Предупреждение» — по строке на каждый элемент `warnings`, текст чистится
  так же, как текст сегмента. При частях у обоих префикс `ч.<i>: `.
- «Сомнительных сегментов» — всегда; список «первые» — до трёх, только при K > 0.
  Сегмент без `confidence` не считается сомнительным; пустой (пропущенный) сегмент
  не считается вовсе.
- Длительность записи — сумма `audio_seconds`, обработка — сумма
  `processing_seconds`; отсутствующее поле → `?`.
- Время `HH:MM:SS` — `floor(секунды + смещение части)`.
- Говорящих — число различных `speaker` (сегменты без метки не считаются).
- Реплика: подряд идущие сегменты с одной меткой в пределах одной части, пока
  следующий сегмент начинается меньше чем через 60 с от начала реплики (уточнено
  финальным ревью 2026-10-02: иначе лекция одного говорящего давала одну строку на
  час). Сегмент без `speaker` — метка `SPEAKER_?`, такие сегменты не склеиваются:
  при `diarize = no` или сбое разметки каждый сегмент — своя строка со своим временем. Текст сегмента: `\r`, `\n`, `\t` → пробел, обрезка
  пробелов по краям; пустой после обрезки сегмент пропускается; сегменты реплики
  соединяются одним пробелом.
- JSON-строки декодируются полностью: `\" \\ \/ \b \f \n \r \t \uXXXX`, включая
  суррогатные пары.
- «Дата» — местное время записи файла; в тестах подменяется переменной окружения,
  реального времени тесты не читают.

### 9.3. Сводка

По файлу — `ok` (говорящих, сомнительных сегментов, этапы не `ok`), `fail`
(причина, `detail` сервера дословно), `skip`. Итог прогона: успешно / провалено /
пропущено / не обработано. Код возврата: 0 — без `fail` и без остановки, иначе 1.

## 10. dry_run

Выполняются только чтения: проверка конфига, выбор адреса (`GET /speech/limits`),
ffprobe. Печатаются план частей, команды ffmpeg извлечения и описание запроса (адрес,
поля формы; без ключа). Извлечения, отправки и записи файлов нет.

## 11. Платформы

- **`.sh`** — новый модуль `asr_client.sh` в `ffmpeg/`, подключается из
  `FFmpeg_Converter_script.sh` так же, как `remote_client.sh`. Совместим с bash 3.2 и
  BSD-утилитами (CI macOS). Печатающие функции не зовутся через `$( )`: результаты —
  в глобальных переменных (`ASR_HTTP_CODE`, `ASR_CURL_RC`, …), как у удалённого
  клиента. Разбор JSON — один процесс `LC_ALL=C awk` на файл: токенизатор JSON,
  декодирование строк в UTF-8, вывод шапки и реплик.
- **`.ps1`** — новый модуль `asr_client.ps1` в `ffmpeg/`, подключается из
  `FFmpeg_Converter_script.ps1` по образцу `remote_client.ps1` (каталог — `guiAppDir`,
  не `$PSScriptRoot`); curl — `curl.exe` (не алиас `curl`), запускается через
  `System.Diagnostics.Process` со stdin под ключ и опросом файла отмены GUI.
  Текст пишется `UTF8Encoding($false)` с `` `n ``; обрезка — только `' ', '\t', '\r', '\n'`
  (не `.Trim()` без аргументов, который режет и NBSP — расхождение с `.sh`).
- **GUI** — группа «Распознавание речи (ASR)» в основной области: флажок режима,
  язык (`ru`/`en`), разметка говорящих, число говорящих, адрес, ключ
  (`UseSystemPasswordChar`). `api_key_command` и `pinned_pubkey` — только из
  `config.ini`, передаются воркеру. GUI `config.ini` не переписывает. Прогресс —
  через существующий файл прогресса: «распознавание: <файл>, часть i/n, ждём сервер
  мм:сс». Модуль входит в EXE (`build_exe.ps1`) и в список исходников, по которым
  `Get-StaleExeSources` ловит устаревший EXE.
- **`.cmd`** — `FFmpeg_Converter_run_v19.cmd` читает ключи `[asr]` и при
  `enabled = yes` печатает `[ПРЕДУПРЕЖДЕНИЕ]` «Распознавание речи ([asr]) в
  CMD-версии недоступно — используйте .sh, .ps1 или GUI» и завершается с кодом 1, не
  конвертируя: молчаливая конвертация вместо расшифровки дала бы не тот результат.

## 12. Тесты

- Клиент `.sh` с моком curl (`CURL_BIN`, маршруты `MOCK_CURL_ROUTES`): выбор адреса
  (таймаут → следующий, `401` и код `90` → остановка), разбор пределов, план частей,
  argv/stdin curl (ключа нет в argv, `-k` только с пином), `503` с повторами,
  матрица «файл провален / прогон остановлен», dry_run без отправки.
- Клиент `.ps1`: те же случаи, мок — переопределённая функция запуска curl.
- Паритет: фикстуры JSON (экранирование, `\uXXXX` и суррогаты, нет `speaker`, нет
  `confidence`, `diarize=failed`, `warnings`, несколько частей) → `.txt` из `.sh` и
  `.ps1` совпадают байт в байт; план частей совпадает на наборе длительностей.
- Сквозной прогон `FFmpeg_Converter_script.sh` в режиме ASR с моками ffmpeg/curl:
  выходы, пропуск готового, `overwrite_existing`, сводка и код возврата.
- CMD: предупреждение и код 1 при `enabled = yes`.
- `test_config_keys` — с учётом секции; `config-key-contract.yaml` — ключи `[asr]`
  в списке «только .sh/.ps1».
- GUI: контролы группы и передача переменных воркеру (по образцу `test_16_gui_state`).
- Живая проверка против сервера — вручную, вне набора (сетевой guard тестов её и
  не пустит): одна короткая запись, затем запись длиннее порога.
