# Тест-система

Точка входа одна: `tests/run_tests.sh`.

```bash
bash tests/run_tests.sh           # всё
bash tests/run_tests.sh ffmpeg    # только ffmpeg
bash tests/run_tests.sh yt-dlp    # только yt-dlp
bash tests/run_tests.sh common    # кросс-платформенные инварианты
bash tests/ffmpeg/test_05_filters.sh   # один файл — тоже полноценный запуск
```

Неизвестный фильтр — ошибка (`exit 2`), а не молчаливое «всё»: опечатка вроде
`commmon` иначе выглядела бы успешным прогоном запрошенного набора.

**Числа тестов и файлов здесь не приводятся.** Итог зависит от платформы (без
`cmd.exe`/PowerShell часть suite'ов пропускается целиком, и один `skip`
заменяет десятки assert'ов), а всякое число в документе устаревает на следующем
же коммите. Источник истины — вывод раннера. Единственное место с числами
файлов — `README.md`, и там их сверяет `tests/common/test_guardrails.sh` с
собственными регистрациями раннера; несверяемое число расходится молча — именно
так эти счётчики и разошлись в прошлый раз.

## Из чего состоит

| Каталог | Что там |
|---|---|
| `tests/lib/framework.sh` | Ассерты и форматированный вывод. Чистый bash, без зависимостей |
| `tests/mocks/` | `ffmpeg`, `ffmpeg.cmd`, `ffprobe`, `yt-dlp`, `curl`, `vot-cli-live` |
| `tests/ffmpeg/` | Тесты ffmpeg-конвертера (SH/PS1/CMD, GUI, удалённый бэкенд) |
| `tests/yt-dlp/` | Тесты загрузчика (SH/PS1/CMD, GUI, лимит длины пути) |
| `tests/common/` | Инварианты, общие для обеих сторон |
| `tests/config-key-contract.yaml` | Контракт ключей `config.ini` ↔ реальность |

Список файлов и краткое описание каждого — в таблицах `README.md`. Дублировать
их здесь незачем: `test_guardrails.sh` требует, чтобы КАЖДЫЙ зарегистрированный
в раннере файл был упомянут в README, и второй список пришлось бы поддерживать
вручную без всякой проверки.

## Как устроен прогон

**Маркер результата обязателен.** Каждый файл заканчивается вызовом `summary`,
который печатает `TESTS_RESULT pass=N fail=N skip=N`. Раннер читает именно его,
а не глифы ✓/✗: те зависят от локали и оформления. Файл без маркера считается
проваленным — иначе одна забытая `summary` перед `exit 0` делала бы весь suite
невидимкой на всех линиях CI.

**Ненулевой код возврата — провал**, даже если все assert'ы прошли: значит suite
умер после них (`set -e`, `exit N`, крах).

**`STRICT_SKIP=1`** (Windows-CI и `tools/check_release.ps1`) превращает в провал
не только целиком пропущенный файл, но и частичный пропуск с причиной вида «не
найден / недоступен / не установлен»: такой пропуск означает, что проверка не
выполнялась, а не что она не нужна.

**Сетевой guard.** `tests/lib/framework.sh` подставляет в начало `PATH` заглушки
`vot-cli-live`, `vot-cli-live.exe` и `curl`, которые печатают громкое сообщение
и выходят с кодом 97 вместо обращения в сеть. Тест, которому такой инструмент
нужен по существу, передаёт мок через `VOT_BIN`/`YTDLP_BIN`/`CURL_BIN` и
добавляет `tests/mocks/` в `PATH` — он выигрывает у guard'а. Guard появился
после реального инцидента: тест перевода 22 секунды разговаривал с живой
службой.

## Правила, которые легко нарушить

- **Тесты работают с НАСТОЯЩИМ кодом.** Inline-копии функций запрещены
  guardrail'ом: копия расходится с оригиналом, и тест начинает проверять сам
  себя. Production-скрипты дот-сорсятся (`BASH_SOURCE`-guard в `.sh`,
  `$env:FFCONV_TEST` / `$env:YTDLP_TEST` в `.ps1`).
- **`grep -qF --`** (с двойным дефисом) для паттернов вроде `-c:v`: иначе они
  разбираются как опции grep.
- **`cmd //c`** (двойной слэш) в Git Bash, не `cmd.exe /c`.
- **`.cmd`-файлы, создаваемые тестом, обязаны иметь CRLF** (`sed 's/$/\r/'`):
  с LF-концами cmd.exe склеивает строки блока `( … )`.
- **`< /dev/null`** при дот-сорсинге скриптов: пауза «нажмите Enter» включается
  только на интерактивном stdin, но перенаправление снимает вопрос целиком.
- **`mktemp_suffix`** вместо шаблона с расширением после `XXXXXX`: BSD-mktemp
  (macOS) такой шаблон не подставляет вовсе.
- **PS1 форматирует `4.0/2.0` как `"2"`**, без десятичной части — ассерты по
  строке atempo должны это учитывать.

## Что проверяют инварианты `tests/common/`

- кодировки файлов (`.ps1` — BOM, `.sh` — без BOM, входные `.cmd` — `chcp`,
  CRLF);
- паритет ключей `config.ini` между платформами и соответствие контракту;
- статические guardrail'ы: запрещённые конструкции (рефлексия к непубличным
  членам, компиляция C# на лету, `::` внутри блоков `.cmd`, `$PSScriptRoot` в
  воркере ffmpeg), транзитивное замыкание «печатающие функции не зовутся через
  `$( )`», числа файлов в README, баннер «АРХИВ» у планов, шаблон `{a,b}` внутри
  вложенных кавычек подстановки (в bash 3.2 он попадает под brace expansion и
  теряет скобки — ловится только при запятой внутри, поэтому и прожил в CI);
- ссылки и пути в документации ведут на существующие файлы;
- барьеры приватности (`pre-commit`, `privacy-scan`) — на настоящих временных
  git-репозиториях; отдельно — что сломанный барьер ПАДАЕТ, а не рапортует
  «чисто»: `privacy-scan` при сбое git печатал «чисто» и exit 0 на дереве с
  приватным IP, то есть подтверждал отсутствие утечки вместо проверки;
- adversarial имена и пути; паритет таблиц форматов yt-dlp SH ↔ PS1;
- самопроверка самого фреймворка.
